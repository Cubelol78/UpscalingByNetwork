# Documentation .gitignore

## Vue d'ensemble

Le fichier `.gitignore` a été complètement restructuré pour couvrir tous les aspects du projet d'upscaling vidéo en réseau.

## Structure

Le `.gitignore` est organisé en 10 sections principales:

### 1. Python
Ignore tous les fichiers Python générés:
- `__pycache__/` - Cache Python
- `*.pyc`, `*.pyo` - Bytecode compilé
- `*.egg-info/` - Métadonnées des packages
- `venv/`, `env/` - Environnements virtuels
- `.pytest_cache/` - Cache des tests
- `.coverage` - Rapports de couverture

### 2. Project specific
Fichiers spécifiques au projet:
- `logs/` - Logs du serveur et client
- `work/` - Dossier de traitement (vidéos, images, audio)
- `*.db`, `*.sqlite` - Bases de données
- `config/server_config.json` - Configs personnalisées (garde default_config.json)
- `.upscaling_client/` - Dossier client de sauvegarde
- Fichiers vidéo (*.mp4, *.avi, *.mkv, etc.) - Trop volumineux pour git

### 3. IDE & Editors
Configuration des IDE:
- `.vscode/` - Visual Studio Code
- `.idea/` - PyCharm/IntelliJ
- `*.sublime-*` - Sublime Text
- `*.swp` - Vim
- `.emacs.*` - Emacs

### 4. OS
Fichiers système:
- `.DS_Store` - macOS
- `Thumbs.db` - Windows
- `.directory` - Linux

### 5. Documentation & Plans
**Fichiers conservés** (prefixés avec `!`):
- README.md
- QUICKSTART.md
- TESTING.md
- DEVELOPMENT_SUMMARY.md
- GUI_GUIDE.md
- SPRINT_10_GUI.md
- CHANGELOG_MAIN.md

**Fichiers ignorés**:
- CLAUDE.md - Instructions privées
- notes.md, TODO.md - Notes personnelles

### 6. Backup & Archive
- `*.bak`, `*.backup`, `*.old` - Fichiers de sauvegarde
- `*.zip`, `*.tar.gz` - Archives

### 7. Security & Credentials
**TRÈS IMPORTANT** - Ignore les fichiers sensibles:
- `.env`, `.env.*` - Variables d'environnement
- `credentials.json`, `secrets.json`
- `*.key`, `*.pem`, `*.crt` - Clés et certificats
- `id_rsa*` - Clés SSH

### 8. Build artifacts
- `build/`, `dist/` - Dossiers de build
- `*.exe`, `*.app` - Exécutables compilés

### 9. Testing
- `test_output/`, `test_videos/` - Fichiers de test
- `htmlcov/` - Rapports de couverture HTML

### 10. Docker
- `docker-data/` - Volumes Docker

## Patterns spéciaux

### Fichiers vidéo
Tous les formats vidéo sont ignorés car trop volumineux:
```
*.mp4
*.avi
*.mkv
*.mov
*.flv
*.wmv
*.webm
*.m4v
```

### Artefacts de traitement
Les fichiers générés pendant le traitement sont ignorés:
```
work/**/*.png      # Images extraites/upscalées
work/**/*.jpg
work/**/*.aac      # Pistes audio extraites
work/**/*.mp3
work/**/*.srt      # Sous-titres extraits
work/**/*.ass
```

### Configuration
- **Garde**: `config/default_config.json` (configuration par défaut du projet)
- **Ignore**: `config/server_config.json`, `config/client_config.json` (configurations personnalisées)

## Vérification

Pour vérifier ce qui est ignoré:
```bash
# Voir les fichiers non suivis
git status --short | grep "^??"

# Voir ce qui serait ignoré
git check-ignore -v <fichier>

# Tester un pattern
git check-ignore -v work/input/video.mp4
```

## Maintenance

### Ajouter une nouvelle exception
Pour forcer le suivi d'un fichier normalement ignoré:
```bash
git add -f fichier_a_forcer.log
```

Ou ajouter une exception dans `.gitignore`:
```
# Ignore tous les logs
*.log

# Mais garde ce log spécifique
!important.log
```

### Nettoyer le cache git
Si des fichiers déjà suivis doivent maintenant être ignorés:
```bash
# Retirer du suivi sans supprimer
git rm --cached fichier.log

# Retirer un dossier entier
git rm -r --cached logs/
```

## Sécurité

⚠️ **IMPORTANT**: Le `.gitignore` protège contre les commits accidentels de:
- Mots de passe (dans .env)
- Clés privées (*.key, *.pem)
- Credentials (credentials.json)
- Vidéos personnelles (*.mp4)

Mais il ne protège **PAS** si:
- Le fichier a déjà été commité avant
- Vous utilisez `git add -f` pour forcer l'ajout

```bash
git ls-files -i --exclude-standard

git rm --cached <fichier>
```

## Exemples d'utilisation

### Développement normal
```bash
# Créer un fichier
echo "mon code" > server/core/new_module.py

# Vérifier le statut
git status
# → new_module.py apparaît (sera suivi)

# Créer un log
echo "log" > logs/test.log

# Vérifier le statut
git status
# → logs/test.log n'apparaît PAS (ignoré)
```

### Traitement vidéo
```bash
# Ajouter une vidéo à traiter
cp ma_video.mp4 work/input/

# Git l'ignore automatiquement
git status
# → Aucune mention de ma_video.mp4

# Les images générées sont aussi ignorées
ls work/frames/*/frame_*.png
# → Tous ignorés par git
```

### Configuration personnalisée
```bash
# Modifier la config par défaut
nano config/default_config.json
git status
# → Apparaît (doit être commité)

# Créer une config personnalisée
cp config/default_config.json config/server_config.json
nano config/server_config.json
git status
# → server_config.json n'apparaît PAS (ignoré)
```
